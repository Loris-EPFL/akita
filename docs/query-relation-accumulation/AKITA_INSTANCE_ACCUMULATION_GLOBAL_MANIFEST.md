## 1. Selected proof grammar

Use one versioned public-coin protocol and one domain-separated Fiat–Shamir transcript for the entire archive. A proof header binds the exact base/challenge fields and basis, setup roles, source/query maps, common alphabets, receiver layout, segment limit, workload shape, original program/public-I/O statement, history mode, sampler law and all matrix certificates.

For each ordered segment:

1. Bind its segment index, active length, original source handles, start/end state, actual first/last expanded PCs and external successor metadata. Check integer limits, role/order/presence, adjacency and program identity. Commitments and all boundary claims precede challenges using them.
2. Run the revised Jolt frontend through the pending stage-8 boundary. Preserve the source-derived stage/alias/point order. New endpoint, padding and boundary queries are ordinary obligations, not successful PCS verification.
3. On each original handle, run its specified full raw-source domain prefix. The generic bounded local scheme includes the old receiver prefix; history-only reuse is an explicitly different optimization.
4. Convert ordinary claims through the fixed gadget digit point, then run same-raw-view multipoint normalization. All input claims precede its independent coefficients. Retain the original P columns and physical source geometry.
5. Compute and bind every native partial/D/H payload before its lattice folding challenge. Fold the old receiver and fresh original sources. Form the complete Eq. (109) witness and bind its actual outgoing commitment.
6. Bind its coefficient-row descriptor; sample the row point rho. Run the complete outgoing range pipeline, retaining its initial anchor tau0, interstage frontiers and final virtual claim. Sample the three independent fused coefficients for the virtual-range, binary and zero terms. Run the degree-three fused coefficient/range sumcheck. Validate its full terminal equation and all metadata. Return the single pending outgoing opening, never “complete proof accepted.”

Initialize with the registered zero receiver, its actual zero commitment/path, and a fixed correctly sized zero-evaluation claim. After the last update, run the final domain/normalization prefix, the three complete shrinking reductions and the direct inner terminal in [the compact profile](AKITA_INSTANCE_ACCUMULATION_COMPACT_PROFILE.md). The verifier replays the entire ordered archive and final decision. A succinct outer receipt is **not** included in this profile or budget.

A scalar-derived bridge must not compress the entire frontend to the current K-valued session seed and then silently claim E entropy. The new native/frontend components consume the same canonical transcript context and typed site namespace. Existing nested-session APIs need an explicit full-context adapter; an unreviewed 16-byte bridge is rejected. This changes Fiat–Shamir framing, not lattice commitments or the arithmetic accumulator relation.

## 2. Stage descriptors

Each canonical descriptor contains `(site, prior-message binding, family, count, degree/arity, order, presence, sampler, dependencies, exceptional-set rule, source handles)`. A macro may contain sequential scalar rounds; grouping it in the certificate does not sample future challenges early or erase intervening prover messages.

| Macro | Full-field charge numerator | Mixed-tree factor |
|---|---:|---:|
| Degree-D sumcheck, mu rounds | D*mu | (D+1)^mu |
| Multilinear reference/row point, k coordinates | k | 2^k |
| Independent affine coefficients, Lambda coordinates | Lambda | Lambda+1 |
| Normalized affine combination, first coefficient one | Lambda-1 | Lambda, only with that chosen grammar |
| Lattice fold, W coordinates in C | W / |C| as a probability | W+1 |
| Fixed public gadget conversion / fixed Boolean metadata query | 0 | 1 |

The first four probabilities divide their numerator by |E|. The selected raw multipoint protocol uses **all independent coefficients**, not the normalized row. Its cost is `Lambda+2*mu_raw`, factor `(Lambda+1)*3^mu_raw`; singleton claims may bypass it. No terminal-factor division is used.

### Outgoing native macro

For base 32, the native paired-root product tree has inner degrees (4,4). Each equality-weighted sumcheck has actual degree five. Its intermediate frontier has four values. Retain the initial mu-coordinate range anchor and the final virtual-meaning sumcheck of degree three. With coefficient-row arity kappa and three independent fused coefficients, a conservative scalar charge is

\[
c_{native}=\kappa+16\mu+6.
\tag{1}
\]

It charges the two five-degree pipelines (10mu), the degree-three fused rounds (3mu), the initial anchor (mu), binary and required-zero anchor reuse (2mu conservatively), the four-child interstage combination (3), and the final three coefficients (3). Reusing anchors adds no *new* tree but must retain their full original interpolation families.

The corresponding complete factor is
\[
(W+1)\,2^\kappa\,16\,288^\mu,
\quad 288=2\cdot6^2\cdot4.
\tag{2}
\]

The factor 16 is the interstage factor four times the final affine-combination factor four. No ring-evaluation challenge is present in the exact coefficient-row mode. No quotient, physical-L2 norm or setup-offload macro is selected.

n_{\rm draws}=4\mu+3+z,\quad

## 3. Frontend and endpoint rows

The [immutable frontend manifest](AKITA_INSTANCE_ACCUMULATION_FRONTEND_MANIFEST.md) specifies every original uni-skip, batch member, degree, reference, gamma exponent, selector, carry and ordering. In particular retain the centered-Lagrange outer tau coordinate, gamma-cubed canonical-address term, even-exponent Booleanity fold, stage-7 decode exponent, and actual prefix-selector draws. The old K sampler is not the new E sampler.

New endpoint rules:

- RAM/integer-register/optional field-register value identities use the incoming prefix state and an outgoing-endpoint combination coefficient. Charge at most `2+f` E coefficients conservatively; [the exact lowering](AKITA_INSTANCE_ACCUMULATION_SEGMENT_LOWERING.md) reuses the existing RAM gamma and adds only the register/field gammas. All endpoint values precede them; degree three and downstream native leaf counts are preserved.
- First/last PC address moments each combine at most bB digit claims independently, then run degree-two sumcheck over k address coordinates. Charge `2bB+4k`; factor `(bB+1)^2*3^(2k)`. The actual first/last PCs and their digits are public and range checked.
- For C_X, use the column-specific restricted equality weights of [main-source reuse](AKITA_INSTANCE_ACCUMULATION_MAIN_SOURCE_REUSE.md), covering inactive cycles and each zero-omitting column's physical address-zero cells. Sumcheck `sum_p alpha_p W_p(x) X_p(x)`; masks differ by column, so do not factor out one common mask. Degree two, charge `3mu_X+P`, factor `2^mu_X*(P+1)*3^mu_X`, and P ordinary leaves are unchanged. The optional C_F logical/physical polynomial zero check has charge `3mu_F`; do not silently require canonical raw gadget digits for a decoded zero.
- Public register endpoints are deterministic canonical K vectors. Legal-cut flags and source identity/range/adjacency checks are deterministic. Committed program needs the five source-bound metadata queries in the segment interface, not five fresh challenges; their normalization is already charged.
- Check original initial RAM once at the existing read/write-derived address, comparing C_R0 with the original public/advice/image initial-table construction. Preserve the staged auxiliary leaves and their reductions. Its complete ancestor address tree supplies the anchor; separately charging up to mu_RAM is a safe overcount. Interior segments do not reinitialize.
- Instantiate the original RamOutputCheck only on the final segment and alias its `RamValFinal` leaf to C_Rfinal. It proves the same `eq*Mask_IO*(Bfinal-Expected_IO)` Boolean identity with its actual padding/phase schedule. The original frontend count covers this retained member. An explicit standalone endpoint variant would cost at most `4mu_RAM` and one leaf; retaining that allowance is conservative. Neither variant adds a host-MMIO/halting predicate.

All moved/extended reductions need the same original-handle extraction linkage. The initial/final public-table functions must be the original proof-side tables; this note does not substitute a stronger emulator or termination relation.

### Conservative catalogue-wide arithmetic ceiling

Require at admission: n_trace<=34, P<=64, c<=256, field/program exclusivity, at most 263 participating handles including the old receiver, every raw/physical/row point arity<=64, and every source/profile included in the registered ledger. The ordinary cap including committed boundary metadata is at most 524; together with raw-prefix endpoints and the old pending claim, the total multipoint list size is at most 788. Then a deliberately loose new-work bound per update is

\[
263(16\cdot64+5)+788+2\cdot64\cdot263
+(64+16\cdot64+6)+3+160+448
=306784.
\tag{3}
\]

The last terms bound native strong work, endpoint coefficients, two PC reductions and main/field inactive checks. The immutable original-frontend bound is 620452 per segment (already includes a conservative factor two). Even charging the new-work sum twice gives
\[
620452+2\cdot306784=1234020<2^{21}.
\]
For 16 segments, the standalone final domain/normalization prefix, three native suffix folds, and once-only initial/final checks remain below `2^26`, under these arity ceilings. The exhaustive frontend audit found no extra error/arity for the inspected gamma-zero, Gruen, Lagrange or inactive-round branches: they are total polynomial implementations. This supports c_E<=2^40 for the specified lowering, not unchanged K-sampling binaries or unlisted future gates.

## 4. Explicit polynomial mixed-tree ceiling

The manifest must emit the actual factor product; adding scalar errors alone does not establish extractability. A deliberately loose independent admission certificate can use the following fixed grammar caps:

- At most H=2^16 macro blocks across the complete declared 16-segment execution and final decision.
- Every scalar interpolation arity is at most 2^16.
- Every nested macro has at most `floor(log2(Nexp+1))+128` coordinates. Nexp includes explicit source, setup, relation-row and descriptor sizes; the additive 128 covers the fixed RISC lookup-address domain.
- Every flat affine/lattice macro has at most Nexp coordinates and child arity at most 2^16.

These are compiler checks, not assertions that an arbitrary new recursion grammar meets them. A macro can compress sequential sumcheck rounds only in this certificate, retaining their actual message/challenge order.

A conservative macro count for this grammar is 2427 per update: at most eight domain/normalizer macros on each of 263 handles, sixteen batch macros, four uni-skip/reference macros, twenty-two other scalar families, one RAM reference, 259 selector macros, nine native macros, and twelve endpoint/zero-check macros. Sixteen updates plus thirty-nine final/once-only macros give **38871 < 65536**. Message/challenge order remains explicit inside each sequential macro. The frontend arities (at most 193 in the cited power families), native scalar arities and flat-fold child arity two are below the registered ceiling; no inspected fallback adds an exceptional family. Implemented descriptors must still reproduce this covered grammar rather than silently adding sites.

Each nested factor is at most `2^2048*(Nexp+1)^16`; each flat factor is smaller than this same bound. Therefore the concrete fixed polynomial
\[
p_{tree}(\lambda,N_{exp})=
2^{2048H}(\lambda+N_{exp}+1)^{16H}
\tag{4}
\]
upper-bounds the complete product whenever the certificate passes. Its degree is fixed before the security parameter/witness size; no growing-depth claim is made. The present fixed number of frontend batches and bounded source groups provides the intended grammar, but the generated macro list must still check these caps, dependencies and actual exceptional-family arities.

Equation (4) is an extremely loose **formal polynomial** bound, not a feasible extraction-runtime estimate or a tight concrete security claim. The MSIS advantages must be evaluated at the whole reduction's expected runtime as in Akita Eq. (227)–(228). A smaller exact product should be reported where available; (4) must not be used to advertise end-to-end 128-bit security.

## 5. Sampler and transcript contract

For E, sample two independent canonical K coefficients, with the nonresidue-5 basis bound in the header. A simple specified bounded sampler tries at most two uniform 128-bit candidates per coefficient, accepting the first below q and aborting if both fail. Conditional on success it is exactly uniform, not modular reduction. Since `(2^128-q)/2^128<2^-96`, per-coefficient abort probability is below `2^-192`. At most 2^40 E samples gives total honest abort probability below `2^-151`. Retry/limb site IDs and every actual raw query belong to the declared Q budget. The cap on samples is separate from the sum of interpolation-degree charges.

For each shell coordinate, choose 40 distinct positions by partial Fisher–Yates over 128 positions. Assign magnitude one to the first 24 selected positions, magnitude two to the next 16, and independently sample 40 sign bits. At step j draw an exactly uniform integer below 128-j by canonical rejection of `ceil(log2(128-j))` bits, with at most 256 attempts; otherwise abort. Each shell vector has the same `24!16!` ordered preimage count. Conditional on no abort, the shell is uniform. A conservative per-position abort bound is 2^-256; at most 2^16 shell coordinates gives total below 2^-234. No response norm filter or nonce search is used.

The conditional raw-tape sampler required by the mixed-tree ROM lemma must also be specified. For E, the number of rejected candidates is independent of the accepted value; draw that truncated geometric count, fill rejected candidates uniformly from `[q,2^128)`, and fix the accepted value. For a shell vector, uniformly order its magnitude-one and magnitude-two position sets, reconstruct each Fisher–Yates index, then apply the same conditional rejection-tape procedure at each index; signs are fixed. Unused tape bytes remain uniform. These distributions have expected-polynomial sampling procedures since every coordinate's acceptance mass is at least one half; conditioning on bounded-sampler success has constant expected overhead. The prover/verifier loops themselves keep their finite caps.

Setup is separately domain separated. The independently reviewed [compact registry](AKITA_INSTANCE_ACCUMULATION_MATRIX_REGISTRY.md) has 33 independent roles and exactly 4681728 expanded K coefficients. At 512-bit modular sampling its bias is below `2^-361`, stronger than the generic `2^40`-coefficient allowance. Do not change already frozen keys or discard the whole-extractor runtime in each MSIS term.
