## Product experiment

Fix all public schemas, guest/ISA, oracle namespaces and the efficient witness-oracle circuit before oracle sampling. Provision actual inner/outer keys under their admitted setup laws. No key/setup expansion is delegated to a concrete hash inside the guest.

Sample independently:

\[
 \Theta_i=(\mathrm{ro}_i,\mathrm{wo}_i,\widehat V_i)
       \leftarrow\mathrm{ARO}[F,m,\lambda_A,d,B_i],
 \qquad H_o\leftarrow\mathrm{RO}_o.
\]

For actual-Theta extraction, fixed B_i may query ro_i but never H_o. For the repaired ordinary-SIS/game lift, explicitly restrict it to **input-local** `B_i(x,mu)=b_i(x,mu,ro_i(x))`. The arithmetization covers only the inner oracle. Setup/auxiliary laws must obey the stated conditioning and accounting; none of this is a concrete-hash theorem.

- Inner native archive verification uses ro_i for its complete Fiat–Shamir challenge protocol and no H_o calls.
- The oracle-query accumulator authenticates Theta_i queries. Its commitment CM is an independently admitted oracle-free lattice commitment, not a Merkle PCS or an assumed homomorphic Akita compression.
- The ordinary outer Akita proof uses H_o for its own Fiat–Shamir transform. It proves an oracle-free skeleton relation R_skel.
- R_skel checks the native archive verifier with supplied query answers, derives every actual query ledger entry, and verifies the oracle-free AS.V. It binds compact run X, installed original C_static, the exact public accumulator acc, and success1.
- The external verifier checks the complete outer proof under H_o and the exact AS.D^{Theta_i}(acc). It does not accept an unbound/private replacement accumulator.

Only one outer proof is required. There is no later layer that must succinctly authenticate H_o evaluations. That distinction is why this route need not instantiate arbitrary-depth PCD in one shared ARO.

## Reviewed product extraction mechanism

Run the actual outer Akita/AFK extractor while forwarding all Theta_i accesses to the **same unchanged oracle**. Reset/fork the prover and condition/program the allowed H_o streams only. Do not reset or rewrite Theta_i answers. The skeleton relation and its deterministic witness checks make no oracle calls.

The [product theorem](AKITA_INSTANCE_ACCUMULATION_PRODUCT_EXTRACTION.md) proves the following two distinct steps under its explicit H1–H5 conditions:

1. Fix the actual Theta_i and prover coins, then apply the original-index mixed-tree sampling to independent H_o, preserving its exact stream laws and the saved original output. Its conditional deterministic projection must return the desired relation witness or a registered matrix collision. The Akita PCS projection is supplied; the full guest projection still needs its separate certificate.
2. For ordinary Module-SIS, run the entire cutoff collision producer through one persistent **paired input-local** emulator, including hidden complementary fetches and the sticky failure state. Charge its aggregate error once before the matrix partition, preserve the single flat shared setup law, and include the corrected complete CPU/cutoff ledger.

Independence matters because programming H_o does not change the graph constraints of Theta_i. The proof supplies the original-run coupling and complete-stream conditioning; independence alone would not have done so.

## Independent construction/cost obligation

The CCGOS general query accumulator materializes a polynomial of degree bounded in terms of `a d N`, where `a=m+lambda_A+w` and `N=n+2ell+1`. Its public accumulator has `2(a+1)` field elements. The private proof and verifier are not constant work.

Derive actual bounds for our complete native verifier, including the full input arity of each hash/XOF operation, output-to-field sampling, transcript framing, rejection attempts, hash graph witness size/degree, CM messages and private field encodings. A variable-input RO cannot silently become a small fixed-input compression oracle without a new transcript theorem. No Jolt trace estimate follows from the number of segments alone.

Compare those derived sizes with the existing byte-advice layout, including the trusted static blob's minimum 128 MiB capacity and the layout's total I/O limit. If the direct CCGOS construction cannot fit, state precisely which construction/profile fails; that is not an impossibility proof for every Akita-based accumulation design. Any proposed improvement needs an actual oracle-authentication/soundness argument, not an unauthenticated query table.

The [independently reviewed cost certificate](AKITA_INSTANCE_ACCUMULATION_ORACLE_QUERY_COST.md) rules out the stated dense-flat representation in the current advice layout. The reviewed [fixed-input compiler](AKITA_INSTANCE_ACCUMULATION_CHAINED_TRANSCRIPT.md) proves its ideal simulation, but its dense T16 illustration still does not fit. The reviewed [lattice-held quotient](AKITA_INSTANCE_ACCUMULATION_ORACLE_QUOTIENT.md) and [one ordinary MLE opening](AKITA_INSTANCE_ACCUMULATION_QUOTIENT_MLE.md) remove that guest-storage/compiler problem conditionally, not their host work, source profile or complete extraction budget.
